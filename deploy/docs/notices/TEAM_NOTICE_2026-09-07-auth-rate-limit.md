# [공지] `/api/v1/auth/` 에 rate limit 이 걸립니다 — 429 를 처리해 주세요

작성: Infra(6번), 2026-09-07
대상: **2번·3번 Frontend (필수)**, 4번·5번 Backend (참고)
관련: MR !85(BE 지갑 로그인), MR !86(FE 지갑 로그인), `TEAM_NOTICE_2026-09-04-wallet-auth-api.md`

---

## 한 줄 요약

`/api/v1/auth/` 로 시작하는 모든 요청이 **IP 당 분당 10회**(순간 최대 20회)로 제한되고,
초과하면 백엔드까지 가지 않고 **nginx 가 429** 를 돌려줍니다.

## 왜

`POST /api/v1/auth/wallet/nonce` 는 인증 없이 열려 있고, 등록되지 않은 지갑 주소면
`WALLET_NOT_LINKED` 로 즉시 거절합니다. 그래서 이 엔드포인트는
**"이 지갑 주소가 우리 서비스에 등록돼 있는가" 를 알려주는 오라클**입니다.
주소 목록을 넣고 돌리면 우리 사용자의 지갑 주소를 골라낼 수 있습니다.

`POST /api/v1/auth/wallet/verify` 도 서명 대입을 반복할 수 있어 같은 제한에 묶었습니다.

백엔드가 아니라 nginx 에서 막습니다 — 애플리케이션까지 가면 이미 DB 조회가 한 번 나간 뒤입니다.

## 설정값

| 항목 | 값 |
| --- | --- |
| 적용 경로 | `/api/v1/auth/` **하위 전체** (`/wallet/nonce`, `/wallet/verify`, 앞으로 추가될 로그인·회원가입 포함) |
| 기준 | 클라이언트 IP (`$binary_remote_addr`) |
| 비율 | `10r/m` — 내부적으로 6초에 1건 |
| 버스트 | `20`, `nodelay` (지연 없이 즉시 통과 후 초과분만 차단) |
| 초과 시 | **HTTP 429** |

`nodelay` 를 쓴 이유: 큐잉으로 응답을 늦추면 사용자는 장애로 인식하고 버튼을 더 눌러
상황을 악화시킵니다. 정상 사용자가 MetaMask 팝업을 몇 번 취소했다 다시 시도하는 정도는
버스트 20 안에 들어갑니다.

## Frontend 가 해야 할 것

**429 를 "서버 장애" 로 표시하지 마세요.** 사용자가 새로고침으로 대응하면 더 막힙니다.

응답 본문은 백엔드 `ApiResponse` 봉투와 **같은 모양**으로 맞춰 두었습니다:

```json
{
  "success": false,
  "code": "TOO_MANY_REQUESTS",
  "message": "요청이 너무 잦습니다. 잠시 후 다시 시도해 주세요.",
  "data": null,
  "timestamp": "2026-09-07T12:34:56+09:00"
}
```

- `code` 는 **`TOO_MANY_REQUESTS`** 입니다. 백엔드 `ErrorCode` 에는 없는 값이므로
  에러 코드 매핑 테이블에 따로 넣어 주세요
- `timestamp` 는 nginx `$time_iso8601` 이라 **오프셋(`+09:00`)이 붙습니다.**
  백엔드 `LocalDateTime` 과 형식이 다릅니다. 이 응답은 애플리케이션까지 가지 않았다는
  뜻이라 일부러 그대로 둡니다 — 파서가 오프셋을 못 읽으면 그 필드만 무시하세요
- 상태코드로 판정하세요. `response.status === 429`

권장 UX: 재시도 버튼을 잠시 비활성화하고 "잠시 후 다시 시도해 주세요" 를 그대로 노출.
자동 재시도를 넣는다면 **지수 백오프**로, 즉시 재시도는 넣지 마세요.

## Backend 가 알아둘 것

- 429 는 **백엔드에 도달하지 않습니다.** 애플리케이션 로그에 남지 않으니
  "요청이 사라졌다" 로 보이면 nginx 로그를 보세요 (`limit_req_log_level warn`)
- `/api/v1/auth/` 아래에 **새 엔드포인트를 추가하면 자동으로 이 제한을 받습니다.**
  분당 10회로 부족한 엔드포인트를 그 아래 두려 하면 미리 알려 주세요
- 나머지 `/api/` 경로에는 제한이 없습니다

## 테스트할 때

로컬(`docker-compose.local.yml`)에는 이 nginx 가 끼지 않으므로 영향이 없습니다.
EC2 에서 자동화 테스트를 돌리다 429 를 만나면 제한 때문입니다 — 필요하면 알려 주세요,
테스트 출발지 IP 를 예외로 빼겠습니다.
