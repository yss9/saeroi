# [공지] `/test/` 상시 통합 테스트 스택 추가 예정 (2026-09-11)

작성: 6번(인프라) · 대상: 전 파트 (backend, frontend, ai)

관련 회의: 2026-09-11 팀 회의에서 합의된 내용입니다. 아래 순서대로 진행 예정이며,
**운영(각 파트 `master`) 배포 흐름은 전혀 바뀌지 않습니다.**

## 1. 무엇이 추가되나

지금까지는 `<파트>/develop`에 병합되면 CI(빌드+테스트)는 도는데, 그 결과물을 실제로
띄워서 확인할 곳이 없었습니다. `https://j15e104.p.ssafy.io/test/`(프론트) ·
`/test/api/`(백엔드) 뒤에, **각 파트 `develop`에 병합될 때마다 자동으로 갱신되는**
상시 통합 테스트 스택을 추가합니다. 새 포트·새 인증서는 없습니다(기존 443 재사용).

이 스택에는 **모든 파트(backend/frontend/ai)의 최신 develop이 동시에 모여** 있습니다.
한 파트가 develop에 병합하면 그 파트 서비스만 재배포되고 나머지는 그대로 유지되므로,
실배포 직전과 같은 조합에서 다른 파트 기능과 함께 확인할 수 있습니다.
`blockchain`은 이미지 빌드 대상이 아니라(컨트랙트는 수동 배포) 포함되지 않습니다.

## 2. 각 파트에 필요한 변경 — Jenkinsfile

`<파트>/develop` 브랜치 빌드에 스테이지를 하나 추가합니다:

1. 이미지 빌드 후 `:test` 태그로 push (기존 `:latest`와 별도 — 운영 배포와 섞이지 않습니다)
2. deploy 서버에 SSH로 `scripts/test-deploy.sh <service>` 호출

**이 Jenkinsfile 변경은 인프라(6번)가 각 파트 브랜치에서 직접 반영합니다** (회의 합의 사항이라
평소의 "다른 파트 파일은 요청 문서로 넘긴다" 절차를 생략합니다). 혹시 각자 Jenkinsfile을
이미 손대고 있다면 충돌을 피하기 위해 미리 알려주세요.

## 3. frontend에 필요한 변경 — `/test/` 서브패스 대응

test 빌드에서만 다음 두 가지가 필요합니다 (운영 빌드는 그대로):

- Vite `base=/test/`
- React Router `createBrowserRouter(routes, { basename: import.meta.env.BASE_URL })`

둘 다 없으면 첫 화면은 뜨지만 내부 링크 클릭 시 `/test` 프리픽스가 빠진 절대경로로 이동해
깨집니다. 인프라가 Jenkinsfile 쪽 빌드 옵션은 넣지만, `router` 코드 쪽 `basename` 적용은
frontend 파트에서 확인 부탁드립니다.

## 4. 아직 아무것도 배포되지 않았습니다

이 문서는 **사전 공지**입니다 (`deploy/feat/test-env` 브랜치 작업 중, 미병합).
실제로 `/test/` 가 응답하기 시작하면 후속 공지로 알리겠습니다.
